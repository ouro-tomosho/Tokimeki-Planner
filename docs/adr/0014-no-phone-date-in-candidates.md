# 电话/约会不进候选；跳过只属于活动日

**Status**: accepted（2026-11-06 所有者裁决）；**取代** ADR-0013 中「求解器改用电话/约会」与「月末两个周日优先电话/约会（软偏好）」两节，ADR-0013 的「指令次数小目标」不变。

## 决策

- **`cmd-date` 不进候选序列**：求解器不选它。但**保留在右键「指定指令」里**，供使用者手动填到休息日——"候选集"（求解器可选）与"可选集"（使用者可填）从此是两个概念。
- **「只在休息日可用」由引擎兜底**（2026-11-06 加固）：以前只有候选集与选择器按 `restOnly` 过滤，**钉住**能绕过它——把 `cmd-date` 钉成整周周指令，周一到周六就照常执行且判定合格。现在 `plan()` 与搜索层共用 `commandBlockReason`，非休息日返回 `rest-only`，当天不结算，界面显示「不结算（休息日专属指令）」。
- **出厂输入不再钉住月末两个周日**。旧默认值把「每月倒数第一、第二个周日优先电话/约会」写成了 `dayCommands` 的默认钉住，而钉住在求解器里是**唯一候选**——软偏好被实现成了硬约束。
- **使用者不能再手工标「跳过」**。跳过只作为活动绑定指令存在（活动日硬空过）。界面上原有的「空过」一律改称「跳过」，右键菜单里的「跳过这一天 / 取消跳过」删除。
- **活动日的指令是日历的底层规则**：活动日右键「指定指令」直接禁用；「清除指定」不会、也无法清掉活动绑定指令。
- 输入版本 4 → 5：加载旧存档时剥掉 `cmd-date` 与显式 `null`（空过）两种标记。

## 背景与理由

旧默认值下，35 个月 × 2 = **70 天**被锁在全 0 效果的 `cmd-date` 上。默认输入实测：结局目标 `eg-science` 差 62.3、`eg-grit` 差 73.2（12 个闸门里 10 个达标）。

三组对照实验（60s 预算，`plan()` 复核）：

| 条件 | 未达标 |
| --- | --- |
| 2 天/月钉住（旧默认） | 2 条（科学、毅力） |
| 只钉 1 天/月 | 1 条（毅力） |
| 完全不钉 | **0 条** |
| 拿掉整本活动日历（仍钉住） | 2 条，缺口只是换了属性 |

缺口随钉住天数线性变化，而删掉活动日历、或把搜索预算加到 5 倍（仍 14.8s 收敛）都救不了——所以原因不是日历、也不是搜索预算，而是这 70 天的硬钉住。

## Considered Options

- **保留 `cmd-date` 作为求解器的"什么都不做"选项**（ADR-0013 的原意）：否决。它效果全 0，等于求解器手里永远是"浪费一天"，而休息日 ×4 的收益远大于什么都不做。
- **把软偏好实现成评分里的小权重**（保留偏好、允许被目标挤掉）：否决。所有者要的是"使用者自己填"，而不是让求解器替他决定哪几个周日去约会；而且偏好与目标抢天数时，计划会随预算漂移，不可复现。
- **只改默认值、保留 `cmd-date` 在候选里**：否决。那样它仍会被随机选进日程，使用者会看到自己没指定的约会日。
- **连「指定指令」里也拿掉**：否决过一版。它在候选里永远是"浪费一天"，但在使用者手里是一条真实记录（游戏里确实要打电话/约会），所以必须留一个手动入口。
- **本决策**：移出候选、留在手动入口；跳过收归活动日。

## Consequences

- 默认输入现在 **12/12 达标**；旧存档加载后同样不再有那 70 天。
- 求解器失去"休息日什么都不做"的自由度，每个结算日都会执行一条真实指令——休息日是 ×4 且可能带负面效果，这是有意的取舍。
- 月末两个周日的"约会"要使用者自己右键填；工具不再替他排。求解器不会在没有指定的情况下产出 `cmd-date`。
- 活动日的格子里只写活动名，不写它绑定的指令：绑定指令由日历决定，写出来只是噪音（`跳过` 仍用斜纹底表达）。
- 输入版本升到 5，旧 `localStorage` 因键名带版本号而自然失效，导入旧 JSON 走 `migrate()` 剥离。
