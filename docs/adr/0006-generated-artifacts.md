# 生成物与构建管道

**Status**: accepted（2026-10-06，所有者裁决）

## 决策

交付物仍是**一个双击即用的网页文件**（根 `index.html`），零依赖、零网络请求。构建管道明确为三段：

```
web/template.html   ── 只放 HTML 骨架、内联 CSS 与占位符，不放任何逻辑
        │
        ├─► plan-core.js     中间产物：src/ 全部逻辑 + data/rules.json，打包成一个文件
        │
        └─► index.html       最终产物：模板 + plan-core.js 内联 + 全部数据内联
```

`web/template.html`、`plan-core.js`、根 `index.html` 中，**后两者是生成物，禁止手改**。`src/` 保持多模块形态，作为唯一的开发源。

构建脚本负责把 `src/` 与 `data/` 内联进产物，因此**产物内不得出现任何外部资源引用**（无 CDN、无外链字体、无图片文件、无 `url()`），测试机械断言其命中数为 0。

## 背景与理由

原先 `web/index.html` 既是人写的模板、又被构建成根 `index.html`，一个文件同时扮演输入与输出；构建脚本把 `web/worker.js` 与 `web/app.js` 当**两个独立入口**分别打包，于是 `data/rules.json` 与整个核心逻辑在产物里各内联**两遍**（`index.html` 里 `rules.json` 出现两次、`createSolver` 出现两次），约 50 KB 是纯冗余。

更要紧的是接线纪律：产物里内联着**旧贪心求解器**，而新写的束搜索只被测试引用、UI 从未加载过。构建是确定性、产物与源码同步的，所以这不是"忘了重新构建"，而是"构建出的东西从来就没接线到新引擎"。

## Considered Options

- **保留手写的单文件 `web/index.html`**：否决。人写的逻辑与生成的产物混在同一路径上，无法机械区分"改动源"和"改动产物"。
- **拆成多个文件、`file://` 下分别加载**：否决。双击打开时相对路径加载 ES 模块在部分浏览器下被拒，破坏"双击即用"。
- **产物里保留两份独立入口**：否决。冗余，且让"产物里跑的是哪个引擎"变得不可机械检查。

## Consequences

- **根 `index.html` 从此不可手改。** 任何逻辑改动都改 `src/`，再重新构建。
- 构建期必须加一条守卫：**产物里不得出现任何已删除模块的引用**，且**测试所运行的求解器与产物内联的是同一个**。这一条正是为了防住上面那个"两代求解器并存、且上线了错的那个"的故障。
- 产物包含全部逻辑与数据，因此**体积会随 `src/` 增长**；这是单文件交付的固有代价，接受。
- `plan-core.js` 作为中间产物的价值是让产物可被**单独测试**（在 Node 里直接加载它跑规则正确性断言，而不必解析 HTML）。它同属生成物，不进版本库。

## 与 ADR-0003 / ADR-0004 的关系

ADR-0003（结果视图以日历为主）与 ADR-0004（规划起点恒为已玩到）继续有效，本决策只改**构建与交付形态**，不改领域语义与界面结构。
