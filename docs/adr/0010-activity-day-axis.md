# 活动日走日指令轴，活动是带条件的硬强制

**Status**: accepted（2026-11-05 所有者裁决）

## 决策

游戏固定日历里的**活动日**走**日指令轴**：即使落在平日，它也读自己的日指令；该周的周指令只作用于非活动日的平日。活动日必须执行其绑定指令，是一条硬约束。活动用「日期区间 + 名称 + 绑定指令 + 适用条件/变体」表达；条件按**活动当天所在社团**解析，命中才生效。休息日与活动日是两个独立标记，可叠加；×4 只由休息日决定。

## 背景与理由

旧模型用 `clubWeeks` 的周锚点强制整周周指令（`clubWeekMandate`），无法表达新日历里逐日的 `club` / `clubCamp` / `skip`：例如文化祭当天是 `skip`，而文化祭集训日是 `club`；整周强制会把文化祭当天也变成社团指令。活动日走日指令轴，才能精确表达“这一天做什么”；活动变体才能表达“同一段日期，棒球社是甲子园、其他社团是暑期集训”。

## Considered Options

- **整周作用域**：改动最小，但单日活动会污染整周，且无法表达文化祭当天与集训日的区别。否决。
- **活动日走日指令轴（本决策）**：精确到天；代价是引擎要区分“休息日（×4）”与“日指令日（休息日 ∪ 活动日）”。
- **只允许活动落在休息日**：会丢掉平日活动（考试、文化祭、全国大赛等），否决。

## Consequences

- 旧 `calendar.clubWeeks`、`clubWeekMandate`、`clubWeekViolation`、`checkClubWeekMandate`、quota 的集训周钉住全部删除。
- 活动日的强制指令由活动解析器 + 日历结构保证，不再靠逐日违规判定。
- 活动条件（体育类/文化类/棒球社）由活动变体表达；求解、判定、界面共用同一个解析器。
- 活动日的 ×4 只在它同时是休息日时生效；`clubCamp` 的社团经验 +2 不受 ×4 影响。
