# 电话/约会指令与指令次数小目标

**Status**: accepted（2026-11-05 所有者裁决）；其中「求解器改用电话/约会」「月末两个周日优先（软偏好）」两节被 ADR-0014 取代，「指令次数小目标」不变

## 决策

新增 `cmd-date`（电话/约会）：日常指令，效果全 0，成功率 0.35，仅休息日可用；求解器不再使用 `skip` 候选，改用电话/约会。活动日的“跳过”是硬空过，与电话/约会不同。每月倒数第一、第二个周日优先电话/约会（软偏好，不是硬约束；活动日优先；时间轴外不适用）。小目标新增“指令使用次数”类型：按执行天数、从游戏开始（含基础次数）、算到截止日前一天、含强制执行、所有指令，`>=` / `<` 均可；日期已过的小目标状态「已过期」（旧称「已跳过」），不进入求解、不计入 `ok`。

## 背景与理由

旧 `skip` 是求解器在休息日的候选，且使用者需要手动空过；完整日历后不需要手动跳过，电话/约会语义更贴近游戏。指令次数目标用于“使用电话/约会 N 次”这类需求。

## Considered Options

- **保留 `skip` 并只改显示名**：改动最小，但“电话/约会”仍不是一条真正的指令，无法计数、无法进小目标；否决。
- **新增 `cmd-date` 并移除 `skip` 候选（本决策）**：语义清晰，可计数；代价是活动日的硬空过要另用 `skip` 表达。
- **把电话/约会做成活动**：无法覆盖“每个休息日可选”的自由度；否决。

## Consequences

- `skip` 从求解器候选与输入移除（活动日的 `skip` 是另一概念：硬空过）。
- 小目标有两种 `kind`：属性求和、指令次数；求解器/判定器/UI 都要支持。
- 过期小目标在求解与 `ok` 中跳过。
- 月末两个周日的偏好只进入搜索排序，不改变硬约束与目标优先级。
