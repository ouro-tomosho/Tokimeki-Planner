# 实时规划：当前日期 = 下一个决策/事件槽，整段求解一次、逐步揭示

**Status**: accepted（2026-11-05 所有者裁决）；**取代** ADR-0003、ADR-0004

## 决策

UI 从“三年全量日历 + 一次算完”改为**实时规划**：左栏输入最后玩到日、当前属性、社团与目标；主区显示当前日期（下一个决策/事件槽）、输出区与“自动计算/手动指定/确认”；单月日历只作记录并跟随当前日期。自动计算对 `当前日期 → 终点` 做一次整段求解，缓存结果，只显示下一个槽；确认后自动显示下一个槽的推荐；手动指定后后续槽留空。整段排程不暴露。记录只存已决定的指令与最终属性；“回到这天”清空之后的记录并取该日记录或默认值。

## 背景与理由

旧 UI 以 3 年日历为主视图，认知负担大；真实用法是周期性回来规划下一步。整段求解的质量优于滚动窗口（[ADR-0009](0009-solver-architecture.md) 的实测），所以保留整段求解、只改展示粒度；“实时”指交互实时，不是每次重算实时。

## Considered Options

- **整段求解 + 逐步揭示（本决策）**：质量最高，复用现有引擎；首次计算 15–20 秒，之后每一步瞬时。
- **滚动窗口（每步重解未来 N 周）**：实时感好，但质量掉一档，且要重做求解器的视界与跨期容量分配。
- **单步贪心**：快但质量最低，否决。

## Consequences

- ADR-0003（日历优先的全量结果视图）与 ADR-0004（起点恒为已玩到）被取代；单月日历是记录视图，不是规划主视图。
- 自动计算缓存失效：手动指定、属性校正、改社团、改目标、回到过去日期。
- 不暴露“深度规划”；整段排程仅内部使用。
- 记录跟随当前日期翻页；未来不显示。

## 与其它 ADR 的关系

- [ADR-0003](0003-calendar-first-result-view.md) / [ADR-0004](0004-frontier-is-played-up-to.md)：被本 ADR 取代。
- [ADR-0009](0009-solver-architecture.md)：求解器架构不变，只改“展示粒度”和“当前日期的推进方式”。
